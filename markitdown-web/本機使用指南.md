# 本機版 · 最簡單用法

目標:**你部電腦有 PDF,想要 .md**。不需要 Vercel、不需要上網(裝完之後)。

---

## 一句話版本

**Windows:雙擊 `PDF2MD.bat`**(舊名 `轉換PDF.bat` 仍然可用,它會轉去同一個程式)
**Mac:雙擊 `轉換PDF.command`**
→ 揀資料夾 → 等 → 自動開結果。

想更方便:先雙擊一次 **`建立桌面捷徑.bat`**,之後桌面上就有個 `PDF轉Markdown` 圖示,
每次只要雙擊它。也可以**把資料夾直接拖到那個圖示上**,連揀資料夾都省了。

---

## 第一步:裝 Python(只需一次)

到 <https://www.python.org/downloads/> 下載並安裝 **Python 3.11 或以上**。

> **Windows 安裝時,第一頁最下面的 `Add python.exe to PATH` 一定要勾。**
> 漏了勾,之後雙擊 `start.bat` 會說「找不到 Python」。

裝完可以驗證一下:開「命令提示字元」輸入 `python --version`,應該顯示 3.11 以上。

---

## 第二步:一鍵安裝 + 啟動(只需一次)

| 你的系統 | 做甚麼 |
|---|---|
| **Windows** | 雙擊 `start.bat`(開網頁版) |
| **macOS / Linux** | `cd markitdown-web && ./start.sh` |

> 如果你**只想把 PDF 轉成 .md**,其實連這一步都可以跳過 ——
> 直接雙擊 `轉換PDF.bat`,它會自己偵測並安裝。

第一次會自動做這些事,約 **2–4 分鐘**:

1. 建立 `.venv` 虛擬環境(不污染你電腦其他 Python)
2. 安裝依賴(PyMuPDF、RapidOCR、OpenCC… 約 400MB)
3. 修正 OpenCV 為 headless 版(見下方「已知陷阱」)
4. 開瀏覽器到 <http://localhost:8000>

之後再啟動就只會跑第 4 步,幾秒鐘。

---

## 第三步:開始轉

### A. 最簡單 → 雙擊「轉換PDF」

| 你的系統 | 做甚麼 |
|---|---|
| **Windows** | 雙擊 **`PDF2MD.bat`** → 跳出資料夾選擇視窗 → 揀好 → 等 |
| **Mac** | 雙擊 `轉換PDF.command` → 系統彈出資料夾選擇 → 揀好 → 等 |

轉完會:

1. 顯示「完成!N 份 .md,用了 X 秒」
2. **自動幫你打開結果資料夾**

**也可以拖放:** 把資料夾(或單一個 PDF)直接拖到 `PDF2MD.bat` / `.command` 上,
不用再揀。單一個 PDF 的話,結果會出在**原檔旁邊**的 `檔名-md` 資料夾。

### B. 少量檔案 → 用網頁

1. 拖檔案進網頁(可一次拖多個,最多 50 個)
2. OCR 選「自動」(預設,只辨識掃描頁)
3. 「版面分析」保持勾選(才會出標題同表格)
4. 按「轉成 Markdown」→ 逐個複製／下載

### C. 想睇進度／改參數 → 用命令列

| 你的系統 | 做甚麼 |
|---|---|
| **Windows** | 把資料夾拖到 `convert.bat` 上(會保留視窗俾你睇 log) |
| **macOS / Linux** | `./convert.sh /path/to/資料夾` |

它會遞迴找裡面所有 PDF(含子資料夾),輸出到**旁邊一個叫 `資料夾名-md` 的新資料夾**:

```
你的文件夾/              你的文件夾-md/
├── 通告/          →     ├── 通告/
│   └── P110-26.pdf      │   └── P110-26.md
└── 表格.pdf             ├── 表格.md
                         ├── _index.json   ← 清單(給網站／Gemini 用)
                         └── _report.csv   ← 逐檔結果報表
```

**不會動你原本的 PDF。** 中途關掉再跑一次會自動跳過已完成的,不用重做。

## 那些常見情況

| 你想 | 做法 |
|---|---|
| 只轉某幾頁 | 先用任何 PDF 工具剪出來,再拖進去 |
| 轉完發現有錯字 | 那是 OCR 的錯;開 `_report.csv` 看哪份 `pages_ocr > 0`,對照原文改 `.md` |
| 要更快 | 加 `--no-layout`:快 3–5 倍,但沒有標題同表格 |
| PDF 本身有文字層 | 完全不會用 OCR,很快(每頁 0.01 秒) |
| 想改輸出位置 | Windows 目前固定輸出到「來源資料夾-mdx」;進階用法見下面 |
| 掃描件好模糊 | 提升解析度:`set OCR_DPI=300`(Windows)或 `OCR_DPI=300 ./convert.sh …` |

### 進階:直接用命令列

```bash
cd markitdown-web
source .venv/bin/activate          # Windows: .venv\Scripts\activate

# 基本
python batch_convert.py /path/to/PDF資料夾 -o /path/to/輸出

# 常用參數
--ocr auto|always|never    # 預設 auto:只辨識沒有文字層的頁
--layout / --no-layout     # 版面分析(預設開)
--workers 2                # 平行處理;4 核以上可設 3–4
--force                    # 全部重轉,不跳過已存在的
--ext pdf,docx             # 只轉這些格式
```

## 已知陷阱(我踩過,幫你避開)

**1. `ImportError: libGL.so.1`**
`rapidocr-onnxruntime` 會硬拉「非 headless」的 `opencv-python`,把 headless 版覆蓋掉。
`start.bat` / `start.sh` 安裝完會自動修正。若你自己用 pip 裝過,手動跑一次:

```bash
pip uninstall -y opencv-python
pip install --force-reinstall --no-deps opencv-python-headless
```

**2. 沒有「版面分析」、輸出全是純文字** ⚠ 這個以前是「靜靜」發生的,現在會大聲警告

**先講硬限制:** PyMuPDF 2.0 在 PyPI 上寫明 `requires_python: >=3.11`。
Python 3.10 只能裝 1.x,而 1.x 沒有 `to_markdown()`,所以**不可能**有標題／表格。
這不是設定問題,是版本問題。

舊版程式遇到這情況會**一聲不響**退回純文字 —— 你就會得到一堆有字、但**沒有標題、沒有表格**
的 `.md`,而且完全看不出有問題。

現在分三層把關:

1. **`_setup.bat` 開跑前先揀 Python** —— 會依序試 `py -3.13` / `py -3.12` / `py -3.11` / `py` / `python`,
   用第一個 ≥3.11 的。一個都找不到就印出大字警告,但仍讓你繼續轉(純文字)。
2. **`.venv` 會自動重建** —— 如果舊 `.venv` 是用 3.10 建的,而你現在裝了 3.12,
   下次雙擊會自動刪掉舊 `.venv` 重建。**不需要你手動刪。**
3. **每次轉換都印環境** ——

```
環境:Python 3.12.4 | pymupdf 2.0 | 版面分析:開 | OCR:可用
```

如果顯示 `版面分析:關`,轉完之後會再印:

```
!! 全部 79 個都沒有版面分析,輸出只有純文字 —— 原因見上面「環境」一節。
```

而且每個 `.md` 的檔頭會寫 `pipeline: pymupdf-text`(正常應該是 `pymupdf-layout`),
`_index.json` 也會有 `"layout_available": false`、`"layout_docs": 0`。

**點修:**

- Python 低於 3.11 → 裝 [Python 3.12](https://www.python.org/downloads/)(勾 `Add python.exe to PATH`),
  再雙擊 `PDF2MD.bat`。`.venv` 自動重建,**不用手動刪**。
- 已是 3.11+ 但版本舊 → 在 `markitdown-web` 開 cmd:
  ```
  .venv\Scripts\python -m pip install -U "pymupdf>=2.0"
  ```

想一次看清楚環境,執行:

```
.venv\Scripts\python _diag_env.py
```

它會列出 Python／PyMuPDF 版本、版面分析、OCR 三項狀態,最後給你一句「結論」。
裝完套件 `_setup.bat` 也會自動跑一次這個。

**3. `start.bat` 閃一下就關**
通常是 Python 沒勾 PATH。重裝 Python 並勾選 `Add python.exe to PATH`。

**4. 第一次轉換特別慢**
RapidOCR 第一次要用到模型(約 15MB,已隨套件附帶,不需下載),之後就快。

**5. 想重裝環境**
刪掉 `markitdown-web/.venv` 整個資料夾,再雙擊 `start.bat` 或 `轉換PDF.bat`。

**6. Mac 雙擊 `.command` 說「未經認證的開發者」/ 沒有執行權限**
在 Terminal 執行一次:
```bash
chmod +x markitdown-web/轉換PDF.command markitdown-web/start.sh
xattr -d com.apple.quarantine markitdown-web/轉換PDF.command 2>/dev/null
```

**7. Windows 雙擊 `.bat`,黑窗一閃即逝** ⚠ 已修,但如果你手上是舊版檔案:

舊版 `.bat` 內容含中文 + `chcp 65001`,cmd 對 UTF-8 批處理的解析不可靠,
會直接中止而不留訊息。新版已全部改為**純 ASCII**(中文只出現在 `.ps1` 裡)。

新版行為保證:
- 執行完**一定會停住**等你看結果,不會自動關窗
- 出錯會顯示錯誤碼,並寫入 `_last-run.log`

如果新版仍然一閃即逝,按順序試:

1. **確認你有解壓縮** —— 直接在 ZIP 裡面雙擊是不行的,
   要先把整個資料夾解壓出來,`PDF2MD.bat` 和 `convert-pdf.ps1` 必須在同一個資料夾。
2. **雙擊 `_diag.bat`** —— 它會產生 `_diag.txt` 並自動用記事本打開,
   裡面有 Python、PowerShell 版本同檔案清單。把那個檔傳給我看就能定位。
3. **手動看錯誤**:開「命令提示字元」,輸入
   ```
   cd /d "解壓後的完整路徑\markitdown-web"
   PDF2MD.bat
   ```
   這樣錯誤訊息會留在畫面上。

**8. 把舊資料夾複製一份來用 → 升級 Python 也救不了** ⚠

`.venv` 是在你電腦上建的,**不會**跟著 ZIP 走,但如果你是把整個
「用過的」資料夾複製一份(例如 `MD-...-md (3)`),`.venv` 會一起被帶過去。

舊版 `PDF2MD.bat` 的邏輯是:

```
if exist ".venv\.deps-ok" goto ready    <- 直接跳過安裝
```

見到 `.deps-ok` 就**連 Python 版本都不檢查**。於是你就會看到:
換了 Python、重新下載 ZIP,但轉出來還是一模一樣的純文字,而畫面一句提示都沒有。

新版已改成先驗證 `.venv` 的 Python 版本:

```
[!] This folder has an old .venv built with Python below 3.11.
    PyMuPDF 2.0 needs Python 3.11 or newer, so that venv cannot
    produce headings or tables. Setup will try to rebuild it now.
```

**正確做法:重裝 Python 之後,重新解壓一個乾淨的 ZIP 到新資料夾,不要複製舊資料夾。**
若真的要用舊資料夾,新版會自動重建 `.venv`;舊版就要自己 `rmdir /s /q .venv`。

想即時知道手上那個資料夾的 `.venv` 是幾版,在該資料夾開 CMD:

```
.venv\Scripts\python -c "import sys, pymupdf; print(sys.version.split()[0], pymupdf.__version__)"
```

| 印出 | 意思 |
|---|---|
| `3.10.11 1.28.2` | 舊的,永遠出純文字 |
| `3.12.4 2.0` | 正常,有標題有表格 |

## 轉完的 .md 放哪裡?

如果你想俾 `gemini/` 問答頁讀:

1. 把 `.md` 按分類放進 repo 的 `knowledge/`
2. 更新 `knowledge/_index.json`(或者直接用 `python batch_convert.py ../out/dl -o ../knowledge` 讓它自己生成)
3. Push 上 GitHub

---

## 唔想用網頁?

`batch_convert.py` 完全唔需要開伺服器,直接命令列跑,最快最省資源。
`start.bat` 只係為咗「拖幾個檔案落去、即刻睇到結果」這個情境。
